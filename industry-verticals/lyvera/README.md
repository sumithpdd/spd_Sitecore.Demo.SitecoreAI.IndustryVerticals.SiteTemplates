# Lyvera — Premium Sports, Entertainment & Event Experiences

Based on [lyveragroup.com](https://www.lyveragroup.com/).

Full documentation: [`docs/LYVERA.md`](../../docs/LYVERA.md) — multi-site architecture, **CM vs generated content**, component inventory, brand portfolio, setup.

## Components (authoring palette)

Twelve **Lyvera** custom renderings are shared across all sites (same React code + same Sitecore rendering items), plus the kit **Promo** from **Page Content**. Each site has its own datasources, variants, and page layouts.

| Map key | Purpose |
|---------|---------|
| `LyveraHeader` / `LyveraFooter` | Partial design chrome |
| `LyveraBanner` | Hero / full-bleed banner (`Default`, `BackgroundText`, **`BrandHero`**) |
| `Promo` | Split/stacked promos (versele-style; from Page Content palette) |
| `LyveraOurBrands` + `LyveraBrandLogo` | Brand logo bar (corporate homepage) |
| `LyveraMultiPromoImageSlider` + `LyveraMultiPromoSlide` | Image gallery + copy |
| `LyveraTextBand` | Simple intro band (optional) |
| `LyveraBrandPageBody` | Brand page sections (`/brands/*`) |
| `LyveraBlogListing` | Blog listing (`/news-and-blog`) |
| `LyveraArticleDetails` | Blog article detail pages |

Starter kit components (`Navigation`, `Container`, …) exist in the repo but are **not** in the Lyvera rendering set — see [redundancies in docs](../../docs/LYVERA.md#redundancies-and-recommendations). **`Promo`** is registered under **Available Renderings → Page Content** (shared kit rendering), not under Lyvera custom renderings.

**Partial designs** (header/footer) are generated by the serialization script. **Page designs** are **not** — create them in CM, attach partial designs, map the headless page template, then pull. See [CM vs generated content](../../docs/LYVERA.md#cm-vs-generated-content).

## Corporate site routes

| URL | Components |
|-----|------------|
| `/` | Homepage (banner, promos, brands bar, portfolio slider) |
| `/brands/{slug}` | `LyveraBanner/BrandHero` + `LyveraBrandPageBody` |
| `/news-and-blog` | `LyveraBanner/BrandHero` + `LyveraBlogListing` |
| `/news-and-blog/lyvera/2026/{slug}` | `LyveraArticleDetails` |

Static fallbacks when CM datasources are empty: `src/lib/lyvera-brand-pages.ts`, `src/lib/lyvera-blog-content.ts`.

Home layout differs from inner pages — see [per-site usage](../../docs/LYVERA.md#per-site-home-component-usage-generated).

## Local development

```bash
cd industry-verticals/lyvera
cp .env.remote.example .env.local
# Set SITECORE_EDGE_CONTEXT_ID and SITECORE_EDITING_SECRET
npm install
npm run dev
```

Set `NEXT_PUBLIC_DEFAULT_SITE_NAME` to `lyvera` or `eventsinternational`.

## Serialization

```bash
node authoring/items/lyveragroup/scripts/generate-lyvera-site.mjs
dotnet sitecore serialization validate --fix -i lyveragroup
dotnet sitecore serialization push -n {YourEnv} -i lyveragroup
```

The generator does **not** write site roots, page designs, or Site Grouping for corporate `lyvera` (`skipInfrastructure: true`).

**Corporate datasources are preserved:** `preserveDataSources: true` means `lyvera/lyvera/Data/*.yml` is **not** deleted or rewritten. CM-pulled fields such as `LogoImage` and `PromoImageOne` (including **SharedFields**) stay intact. After authors change images or copy in CM, pull:

```bash
dotnet sitecore serialization pull -n {YourEnv} -i lyveragroup
```

The generator **does** refresh inner pages (`Home/brands/*`, `Home/news-and-blog/*`), Home layout, variants, and shared renderings.

After changing page designs in CM:

```bash
dotnet sitecore serialization pull -n {YourEnv} -i lyveragroup
```

After adding or renaming React components:

```bash
npm run sitecore-tools:generate-map
npm run lint
```

## Deploy

- **One rendering host** serves all Lyvera Group sites (`lyvera`, `eventsinternational`, …)
- Site grouping `RenderingHost`: **`lyvera`** on every site
- `NEXT_PUBLIC_DEFAULT_SITE_NAME=lyvera` (or `eventsinternational` for brand dev)
