# Brother Content Hub ↔ Sitecore media maps

Generated by the Brother media scripts under `authoring/items/brother/scripts/`.

**Do not commit secrets.** Credentials stay in a local `set-ch-env.ps1` outside git (OneDrive `_content-ready`). Never put client secrets, passwords, or API tokens in this folder or in `docs/`.

## Map files

| File | Purpose |
|------|---------|
| `content-hub-asset-registry.csv` | **Deduped** assets — one row per `LocalFile` (`ContentHubAssetId`, `DamId`, `PublicUrl`, Brand / AssetType / UsageTag) |
| `content-hub-asset-metadata.csv` | Result of metadata apply (Brand / type / tag) |
| `sitecore-cms-image-map.csv` | Sitecore item path + Image field → CH ids + `SerializationStatus` |
| `brother-sitecore-image-field-map.csv` | Planned CMS fields (includes devices + Product Listing datasources) |
| `device-image-field-plan.csv` | Device tree + Product Listing Image wiring from seed script |
| `serialized-image-scan.csv` | Image fields currently present in brother YAML |
| `web-product-download-manifest.csv` | (also under `_content-ready/ch-upload`) Provenance: page URL → local file |

## Pipeline (same for deck media + live Brother site images)

```text
1) Import-BrotherWebProductImages.ps1
     scrape/curate images from brother.co.uk + store.brother.co.uk
     → _content-ready/web-products/web-*.jpg (+ field plan CSV)

2) Upload-BrotherContentHub.ps1
     upload new LocalFiles only (skips names already in upload-manifest.json)
     create public links
     → content-hub-asset-registry + brother-sitecore-image-field-map.csv

3) Set-BrotherContentHubMetadata.ps1
     Brand = Brother
     Type  = Social Media Asset
     Tag   = Used in CMS

4) Sync-BrotherContentHubMedia.ps1
     rebuild maps / optionally -ApplyPatch YAML / -DownloadLocal public/images
```

### Serialization status

| Status | Meaning |
|--------|---------|
| `InSync` | YAML `dam-id` matches registry |
| `MissingSerialization` | Planned CMS field; page/item has no Image value in YAML yet |
| `LocalPublicOnly` | YAML still `/images/...` only |
| `StaleDamId` | YAML has an older `dam-id` — run `-ApplyPatch` |
| `SitecoreMediaLibrary` | Uses `mediaid="{…}"` instead of DAM |

## Deduplication rules

- One **LocalFile** name → one Content Hub asset (`DamId` / `ContentHubAssetId`).
- Many Sitecore fields may share the same `DamId` (no re-upload).
- `Upload-BrotherContentHub.ps1` loads `upload-manifest.json` and **skips** files that already have a `PublicUrl`.
- Only add a new `web-*` / `product-*` file when it is absent from `content-hub-asset-registry.csv`.
