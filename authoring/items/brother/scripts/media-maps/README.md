# Brother Content Hub ↔ Sitecore maps (DAM + PCM + CMS)

Generated by the Brother scripts under `authoring/items/brother/scripts/`.

**Do not commit secrets.** Credentials stay in a local `set-ch-env.ps1` outside git (OneDrive `_content-ready`). Never put client secrets, passwords, or API tokens in this folder or in `docs/`.

## Three layers

| Layer | Content Hub / Sitecore | Inventory file |
|-------|------------------------|----------------|
| **DAM assets** | `M.Asset` + public links → Sitecore Image `dam-id` | `content-hub-asset-registry.csv`, `sitecore-cms-image-map.csv` |
| **PCM products** | `M.PCM.Product` in [ch-products](https://starter-verticals-2.sitecoresandbox.cloud/en-us/ch-products) | `content-hub-product-registry.csv` |
| **XM Cloud CMS** | Serialized pages/datasources (`brother-scs`) | YAML under `serialized-content/` |

PCM products **reuse** the same master assets the CMS Image fields already reference. They do not replace Sitecore PDPs unless you add a product connector later.

## Map files

| File | Purpose |
|------|---------|
| `content-hub-asset-registry.csv` | **Deduped** assets — one row per `LocalFile` (`ContentHubAssetId`, `DamId`, `PublicUrl`, Brand / AssetType / UsageTag) |
| `content-hub-asset-metadata.csv` | Result of metadata apply (Brand / type / tag) |
| `content-hub-product-registry.csv` | **Deduped** PCM products — one row per `Sku` (product id, family, Sitecore path, master asset ids, portal URL) |
| `content-hub-product-family-registry.csv` | Brother Labelling / Printers / Scanners / Supplies families |
| `sitecore-cms-image-map.csv` | Sitecore item path + Image field → CH ids + `SerializationStatus` |
| `brother-sitecore-image-field-map.csv` | Planned CMS fields (includes devices + Product Listing datasources) |
| `device-image-field-plan.csv` | Device tree + Product Listing Image wiring from seed script |
| `serialized-image-scan.csv` | Image fields currently present in brother YAML |
| `web-product-download-manifest.csv` | (also under `_content-ready/ch-upload`) Provenance: page URL → local file |

## Pipeline

```text
1) Import-BrotherWebProductImages.ps1
     scrape/curate images from brother.co.uk + store.brother.co.uk
     → _content-ready/web-products/web-*.jpg

2) Upload-BrotherContentHub.ps1
     upload new LocalFiles only (skips names already in upload-manifest.json)
     create public links
     → content-hub-asset-registry + field map CSV

3) Set-BrotherContentHubMetadata.ps1
     Brand = Brother / Type = Social Media Asset / Tag = Used in CMS

4) Sync / Update-BrotherCmsImageInventory.ps1
     rebuild CMS image maps; optionally -ApplyPatch YAML

5) New-BrotherContentHubProducts.ps1
     ensure product families
     create M.PCM.Product per demo SKU (skip if ProductNumber exists)
     BrandToProduct + PCMProductFamilyToProduct + PCMProductToMasterAsset
     → content-hub-product-registry.csv
```

### PCM product relations

| Relation | Role |
|----------|------|
| `BrandToProduct` | Parent = Brother brand |
| `PCMProductFamilyToProduct` | Parent = Brother Labelling / Printers / Scanners / Supplies |
| `PCMProductToMasterAsset` | Children = existing `M.Asset` ids from the asset registry |

### Serialization status (CMS images)

| Status | Meaning |
|--------|---------|
| `InSync` | YAML `dam-id` matches registry |
| `MissingSerialization` | Planned CMS field; page/item has no Image value in YAML yet |
| `LocalPublicOnly` | YAML still `/images/...` only |
| `StaleDamId` | YAML has an older `dam-id` — run `-ApplyPatch` |
| `SitecoreMediaLibrary` | Uses `mediaid="{…}"` instead of DAM |

### Product registry status

| Status | Meaning |
|--------|---------|
| `Created` | New `M.PCM.Product` this run |
| `Existing` | SKU already present — create skipped |
| `UpdatedRelations` | Existing product; brand/family/assets refreshed |
| `WouldCreate` | `-WhatIf` only |

## Deduplication rules

- One **LocalFile** name → one Content Hub asset (`DamId` / `ContentHubAssetId`).
- One **Sku** (`ProductNumber`) → one `M.PCM.Product` (script skips create when SKU exists).
- Many Sitecore fields / PCM products may share the same asset (no re-upload).
- `Upload-BrotherContentHub.ps1` loads `upload-manifest.json` and **skips** files that already have a `PublicUrl`.
